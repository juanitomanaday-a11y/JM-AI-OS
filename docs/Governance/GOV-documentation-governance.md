# GOV-documentation-governance.md — Documentation Governance

**Status:** Draft. **Document type:** Governance.

This document is the charter for how documentation is governed in this
repository. It establishes the governance layer and points to the specific
standards that implement it. It does not repeat rules already established
in `SYSTEM_RULES.md`; it operationalizes the documentation-related rules
found there.

## Purpose

To ensure every document in this repository — regardless of type — is
created, reviewed, approved, versioned, and maintained the same way, so
the repository stays internally consistent as it grows.

## Scope

Applies to every document in the repository: SOPs, Templates, Reports,
Governance Documents, and the core documents (`README.md`,
`SYSTEM_RULES.md`, `OPERATING_MODEL.md`, `CONTRIBUTING.md`, and the
`/data` READMEs). Where a governance standard would conflict with
`SYSTEM_RULES.md`, `SYSTEM_RULES.md` prevails — it is the constitution.

## Authority

1. JM is the final approver of every document, per `SYSTEM_RULES.md`
   rule 21. Nothing in this governance layer changes that.
2. Governance Documents themselves follow the same review and approval
   process as any other document (`GOV-documentation-review-process.md`,
   `GOV-approval-process.md`).
3. Nothing in this governance layer authorizes a workflow, tool, or
   automation not already permitted by `SYSTEM_RULES.md`.

## Structure of the governance layer

Governance Documents live in `docs/Governance/`, named
`GOV-<short-name>.md`, per `GOV-naming-convention-standard.md`. The full,
current list of governance standards is maintained in
`docs/Governance/README.md`.

## How this layer relates to Batch 1

`SYSTEM_RULES.md` sets non-negotiable rules. `OPERATING_MODEL.md` and
`CONTRIBUTING.md` describe how work actually gets done. This governance
layer sits alongside them: it defines the standards that documentation —
including SOPs, Templates, and Reports — must meet, without changing the
constitution or the existing operating workflow.
